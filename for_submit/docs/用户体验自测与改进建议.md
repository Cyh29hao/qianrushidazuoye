# 用户体验自测与改进建议

更新时间：2026-06-09

本文记录当前 v2.2 版本以普通用户视角运行后的体验结果。它不是最终提交报告，而是后续继续打磨 demo 的工作清单。

## 本轮实际体验范围

- 源码版启动：使用 `pc_host/.venv/Scripts/python.exe pc_host/app.py` 等价启动 6 秒，未出现 stderr、`Could not parse stylesheet`、Traceback 或 `DeprecationWarning`。
- Release 启动：使用临时 `SMARTCLOCK_PROFILE_DIR` 启动 `build_release/SmartClockHost-v2.2/SmartClockHost.exe`，进程正常保持运行；烟测生成的 config/runtime/logs 保留在临时目录并在结束后删除，不污染用户当前配置。
- 页面巡检：在约 1600x900 窗口下分别截图检查 DAY/NIGHT 的主页、系统设置、闹钟与日程管理、调试与测试 4 个页面。
- 自动测试：运行 `pc_host/run_extension_checks.py --host-only`，host-only 通过。
- 打包：通过英文临时路径绕开 PyInstaller/PyQt5 在中文路径下解析 Qt plugin 目录乱码的问题，重新生成 v2.2 exe 和 zip。
- 截图证据：当前截图保存在 `tmp/ui_native_selfcheck/`，仅作本地验证，不提交 Git。

## 本轮已直接修改

- 右侧数字孪生展示区改为不滚动的一屏布局：缩小 7SEG、LED、虚拟按键和间距，右侧固定约 500px 宽，8 位数码管、LED、两行按键和日志摘要完整显示。
- 左侧页面保留纵向滚动但禁止横向滚动；系统设置、日程、调试页当前截图中横向滚动最大值为 0。
- 系统设置继续瘦身：蜂鸣和 LED 掩码放到“调试与测试”，语音播报入口放到闹钟/日程具体模块，不再堆在系统设置。
- 协议测试台重构为完整指令模板下拉框；“缩写当前指令”和“随机混合大小写”都作用于当前文本框，而不是旧的一条 demo。
- 自动测试只保留手动触发，逐项输出 OK/FAIL/SKIP，并把 TX/RX/INFO 同步写入主日志。
- README、测试指南、验收对照、AGENT 规则和 UI 自检清单已同步当前功能。

## 当前体验结论

- 主窗口左右分栏现在稳定：右侧不覆盖左侧，左侧不横向滚动，底部状态栏不遮挡主内容。
- 右侧数字孪生镜像无需滚动即可一屏看全；第二行按键没有被日志区裁切。
- DAY/NIGHT 两套主题在截图中没有白底、黑字不可见、按钮变灰等明显问题。
- 下拉框箭头、checkbox 勾选、蓝色主按钮风格在主要页面可见且一致。
- 主页数据看板保留卡片式展示；串口状态位于串口连接模块和底部状态栏，没有塞回数据看板。
- 天气/NTP/自动测试流程已有 timeout/fallback，UI 不应因网络慢而长期假死。

## 建议后续优化

1. 用真实 S800/COM5 跑一遍 RESET、断电重插、连接后自动写时、USER2 天气短显和自动测试串口步骤，这是当前最重要的硬件验证缺口。
2. 双击 release exe 在用户常用分辨率和 DPI 下再看一次普通窗口、最大化、DAY/NIGHT 首屏，确认截图结果和真实桌面一致。
3. 自动测试页面可以进一步增加“当前目标：离线 host-only / 串口联测”的醒目标识，减少老师看到 SKIP 时的误解。
4. 日志区现在可读，但仍偏工程化；演示时优先展示“已连接板端”“已同步时间”“天气已更新”“USER2 天气短显”等高价值日志。
5. 若后续继续打包，优先从 `C:\smartclock_latest` junction 或英文临时路径执行 PyInstaller，避免中文路径导致 Qt plugin hook 乱码。

## 建议手动测试顺序

1. 双击根目录 `launch.bat`，确认能进入 PC 上位机。
2. 不接板子浏览四个页面，切 DAY/NIGHT，确认无白底、无裁切、无漂浮标题、无右侧滚动条。
3. 点击系统设置里的 DAY/NIGHT、FORMAT、显示开关，确认离线数字孪生能正常变化且日志有提示。
4. 点“一键对时、刷新天气并应用”，确认日志先出现“已开始更新”，等待期间仍能切换页面、看日志和操作其它控件。
5. 接 S800 后选择 COM5 连接，确认连接成功后自动写入当前时间，数字孪生优先显示板端真实帧。
6. 按板端 RESET，观察 PC 数字孪生是否显示开机帧、MODE 是否保持 DAY/NIGHT、后台对时/天气是否不抢占镜像。
7. 运行自动测试，确认每个测试点都有 OK/FAIL/SKIP 输出，失败时有排查提示。
