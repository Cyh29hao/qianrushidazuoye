## 2. 参数语法对照探针

在 `*RST` 后等待约 7.5 秒，避开开机动画，再分别发送老师语法和项目当前语法。

### 日期

```text
>> *SET:DATE YEAR MONTH DATE 2026 06 15
<< ERROR PARAM

>> *SET:DATE YEAR 2026 MONTH 06 DATE 15
<< OK

>> *GET:DATE
<< OK 26.06.15
```

### 时间

```text
>> *SET:TIME HOUR MIN SEC 12 30 45
<< ERROR PARAM

>> *SET:TIME HOUR 12 MIN 30 SEC 45
<< OK

>> *GET:TIME
<< OK 12.30.45
```

结论：

- 老师要求：字段列表在前，数值列表在后。
- 当前实现：字段和值交替出现。
- 这不是延迟或大小写问题，而是协议语法不兼容。

## 3. 缩写边界探针

```text
>> *SET:DATE MONTH 07
<< OK

>> *SET:DATE MONT 08
<< OK

>> *SET:DATE MON 09
<< OK

>> *SET:TIME MIN 31
<< OK

>> *SET:TIME MI 32
<< ERROR PARAM

>> *SET:FOR RIGHT
<< OK
```

结论：

- `MINute` 的最短长度 3 正确。
- `MONTH` 全大写，不应允许 `MON/MONT`，当前错误接受。
- `FORMAT` 全大写，不应允许 `FOR`，当前错误接受。
- 老师 L044 虽显示通过，但只是因为分组语法先在 `YEAR MONT` 处把 `MONT` 当作 YEAR 的数值解析失败，没有真正验证 MONTH 缩写边界。

## 4. 非 ASCII DISPLAY 事件

成功执行交替语法的 SET DATE/TIME 后，稳定捕获到一条损坏的 DISPLAY 事件：

```text
*EVT:DISP <C0><01> 1C
```

原始字节：

```text
2A 45 56 54 3A 44 49 53 50 20 C0 01 20 31 43 0D 0A
```

随后板端又会发送正常事件，例如：

```text
*EVT:DISP 12_34_56 24
```

这说明：

- 命令应答 `OK` 和后续显示可能正常；
- 但第一次强制刷新上报存在二进制污染；
- 违反 ASCII、8 字符定长和 `dpHex` 规范；
- 可能导致 PC 数字孪生忽略帧、日志出现替换字符或状态短暂错误。
